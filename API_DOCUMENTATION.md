# LANDGUARD AI — Backend API Documentation

Base URL:

http://127.0.0.1:5000

All APIs return JSON.

---

## 1. Dashboard

### GET /api/dashboard

Returns overall dashboard information.

---

## 2. Risk Zones

### GET /api/risk-zones

Returns all risk zones.

Optional GeoJSON format:

GET /api/risk-zones?format=geojson

### GET /api/risk-zones/{zone_id}

Returns details of one risk zone.

### POST /api/risk-zones

Creates a new risk zone.

Example JSON:

{
  "name": "Zone B",
  "risk_level": "High",
  "latitude": 16.5100,
  "longitude": 80.6520,
  "risk_score": 85,
  "rainfall": 180,
  "soil_moisture": 80
}

---

## 3. AI Risk Prediction

### GET /api/prediction

Returns the current AI prediction API status/contract.

### POST /api/predict

Receives AI prediction input.

Expected input:

{
  "latitude": 16.5062,
  "longitude": 80.648,
  "rainfall_mm": 185,
  "slope_deg": 30,
  "elevation_m": 500,
  "soil_clay_percent": 25,
  "soil_sand_percent": 40,
  "land_cover": "Forest"
}

Note:
The backend currently accepts the prediction contract but does not generate fake AI predictions.

The actual ML model will be integrated when the AI/ML team provides the model files.

## 5. Alerts

### GET /api/alerts

Returns active/system alerts.

### POST /api/alerts

Creates a new alert.

Example JSON:

{
  "latitude": 16.510,
  "longitude": 80.652,
  "risk_score": 85,
  "risk_level": "VERY_HIGH",
  "trigger_reason": "AI risk score exceeded 75",
  "affected_area": "Hillside Road, Zone B",
  "recommended_action": "Deploy inspection team immediately"
}

---

## 6. Field Reports

### GET /api/reports

Returns field reports.

Optional GeoJSON format:

GET /api/reports?format=geojson

### GET /api/field-reports

Alias for field reports.

### POST /api/reports

Creates a field report.

Example JSON:

{
  "report_type": "Field Officer Report",
  "hazard_type": "Landslide",
  "description": "Critical landslide observed near the main road.",
  "latitude": 16.518,
  "longitude": 80.660,
  "severity": "CRITICAL",
  "weather": "Heavy Rainfall",
  "user_id": "field_officer_03"
}

Critical reports can automatically create an alert.

### POST /api/reports/upload

Uploads a field report image using multipart/form-data.

### GET /api/uploads/{filename}

Returns an uploaded report image.

## 8. Impact Analysis

### GET /api/impact

Returns current impact-related information such as:

- Population exposed
- Villages affected
- Infrastructure
- Field reports
- Risk zones
- Active alerts
- Priority results

---

## 9. Priority Analysis

### POST /api/priorities

Stores a priority analysis result generated by the Impact & Disaster Response team.

### GET /api/priorities

Returns stored priority results.

The backend stores the priority result but does not duplicate the team's scoring logic.

---

## 10. Offline Synchronization

### GET /api/sync/status

Returns synchronization status.

### POST /api/sync

Synchronizes offline field reports with the backend.

Example:

{
  "reports": [
    {
      "report_type": "Offline Field Report",
      "hazard_type": "Rockfall",
      "description": "Rocks found blocking the roadside.",
      "latitude": 16.515,
      "longitude": 80.657,
      "severity": "HIGH",
      "weather": "Heavy Rainfall",
      "user_id": "field_officer_02"
    }
  ]
}

## 11. Database Test

### GET /api/db-test

## Response Format

Successful response:

{
  "success": true,
  "data": {}
}

Error response:

{
  "success": false,
  "error": "Error message"
}

## Important Integration Rule

Frontend, GIS, AI/ML, Field Reporting, Alerts and Impact/Priority modules should use these API contracts.

Do not change existing database columns or API response structures without coordinating with the Backend developer.
